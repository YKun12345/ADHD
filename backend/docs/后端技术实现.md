# 后端技术实现（AB 合并版）

> 当前技术说明。历史接口结论已移动到 `docs/history/`，实际可复现结果以 `docs/evidence/verification-report.md` 为准。

## 架构

- FastAPI 提供 `/api/v1` 业务接口、`/docs` 和健康检查。
- SQLAlchemy 2 同时支持开发 SQLite 与部署 MySQL。
- JWT 鉴权区分 patient、researcher 和 DAC 子角色。
- A 微信小程序是患者主端，`doctor-web/` 是医生/研究人员 Web。
- `findviz/` 通过兼容挂载提供影像可视化；`HGST-main/` 保存模型工程。

## 关键数据链路

- 行为量表：ASRS 与 SNAP-IV。
- 七类认知任务：`reaction`、`simple_reaction`、`stroop`、`trail`、`flanker`、`nback`、`digit`；别名由统一契约层归一化。
- 追踪与报告：每日记录、汇总趋势和综合报告。
- 医生工作流：患者列表、综合报告、影像上传/可视化、关怀任务和 DAC 审计。
- 上传链路：校验扩展名与大小、持久化文件、记录 SHA-256/操作者/状态，再建立预测来源关系。
- 模型边界：真实 HGST 推理和演示 Mock 使用独立接口；真实失败不得伪装成 Mock 成功。

## 配置与数据库

配置由 `backend/app/core/config.py` 从 `backend/.env` 加载；模板只有根目录 `.env.example`。开发默认 SQLite，生产要求显式 `DATABASE_URL` 和非占位 `SECRET_KEY`。

`python -m backend.create_tables` 用于空白开发库建表，`python -m backend.scripts.seed_demo_data` 加载可重复的演示数据。MySQL 初始化入口为 `backend/sql/init_mysql.sql`。生产结构变更仍需专门的迁移和备份流程。

## 启动与页面

```bash
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

医生端为 `http://127.0.0.1:8000/doctor-web/`，接口文档为 `http://127.0.0.1:8000/docs`。局域网和真机配置见同目录 `内网访问方案.md`。

## 已知工程债务

- FastAPI `on_event`、Starlette WSGI 中间件和少量 Pydantic class `Config` 会产生弃用警告，后续应迁移到 lifespan、ASGI 适配和 `ConfigDict`。
- `Base.metadata.create_all` 适合开发初始化，不替代正式数据库迁移系统。
- 模型权重、医院网络、HTTPS、微信平台配置和医学阈值均需外部专业验收。
