# 内网访问方案（AB 合并版）

本说明用于微信开发者工具、局域网真机和医生端演示。不要在不可信网络上传真实患者数据。

## 1. 启动监听

从仓库根目录执行：

```bash
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

`0.0.0.0` 允许同一局域网设备连接，但 Windows 防火墙仍可能需要只对“专用网络”放行 Python/8000 端口。完成演示后应关闭服务和不再需要的防火墙规则。

## 2. 电脑自检

- `http://127.0.0.1:8000/api/v1/health`
- `http://127.0.0.1:8000/doctor-web/`
- `http://127.0.0.1:8000/docs`

## 3. 局域网设备

用 `ipconfig`（Windows）或 `ip addr`（Linux）找到电脑的局域网 IPv4，例如 `192.168.1.50`。手机和电脑连接同一可信 Wi-Fi 后访问：

```text
http://192.168.1.50:8000/api/v1/health
http://192.168.1.50:8000/doctor-web/
```

小程序“服务器连接设置”填写 `http://192.168.1.50:8000/api/v1`。只在开发工具或内部演示阶段按团队规范关闭合法域名校验。

## 4. 正式或公网环境

微信正式版必须使用 HTTPS，并在微信公众平台配置 request 合法域名、有效证书和备案。公网部署还需要反向代理、访问控制、日志脱敏、数据库备份、密钥管理和医院合规审查；临时隧道地址不应作为正式配置。

## 5. 故障定位

1. 电脑先请求健康检查；失败则检查进程和 `backend/.env`。
2. 手机请求同一局域网 IP；失败则检查 Wi-Fi 隔离、防火墙和监听地址。
3. 小程序请求失败时核对 base URL 是否包含 `/api/v1`、开发工具合法域名开关和真机 HTTPS 限制。
4. 医生端必须访问 `/doctor-web/`，旧 `patient_*.html` 已归档，不是活动入口。
