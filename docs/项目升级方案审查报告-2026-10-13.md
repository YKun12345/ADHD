## 4. 逐项审查与修改建议

### R01：不可信网页文本渲染必须进入 P0

**方案依据：** [安全能力表](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:290)、[P0 退出条件](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:497) 强调访问、同意、加密与外发，没有明确列入浏览器渲染安全。

**代码事实：** [医生患者列表](C:/Users/Lenovo/Desktop/ADHD-AB协作版/doctor-web/js/doctor_patients.js:221) 将 `patient_name` 直接插入 `row.innerHTML`；[用户记录卡](C:/Users/Lenovo/Desktop/ADHD-AB协作版/patient-web/js/tracking.js:137) 同样插入 `log.note`。姓名通过 [注册字段](C:/Users/Lenovo/Desktop/ADHD-AB协作版/backend/app/schemas/auth.py:13) 与 [注册保存](C:/Users/Lenovo/Desktop/ADHD-AB协作版/backend/app/api/routes/auth.py:73) 进入数据库，医生接口返回原姓名；备注也是原文保存/返回。认证 token 位于同源页面脚本可读取的 localStorage。

**触发与影响：** 含可执行 HTML 属性的姓名在合法绑定医生查看列表时被当成 HTML 解析，可能在该医生会话内读取或操作其权限范围数据。存储加密和服务端关系检查不能消除合法会话中的脚本执行。本轮确认了输入到危险渲染点的路径，未在真实浏览器执行攻击，未声称已发生盗号。

**应修改：** 把所有用户文本、审核意见、消息和模型文本的安全渲染加入 P0；普通文本用 `textContent`/文本节点，需富文本的地方单独约束允许内容。内容安全策略作补充防护。不要靠限制姓名字符或数据库加密替代输出渲染防护。

**验收：** 合成 HTML 姓名与备注在医生列表、报告和追踪页只显示文字；无事件执行、无 token 读取。应覆盖旧页面，不只覆盖新增审核页面。

### R02：网页账号隔离必须覆盖多个标签与迟到响应

**方案依据：** [复用会话隔离](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:46)、[缓存命名空间](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:452)。原则正确，现有网页实现不能直接作为该保证的基础。

**代码事实：** [患者网页请求](C:/Users/Lenovo/Desktop/ADHD-AB协作版/patient-web/js/api.js:53) 与 [医生网页请求](C:/Users/Lenovo/Desktop/ADHD-AB协作版/doctor-web/js/api.js:53) 每次即时读取共享 token；第 103—105 行处理旧请求 401 时直接删除当前 token/user；请求成功返回也没有核对页面所属会话。

**复现：** 标签 A 持有 A 用户答案，另一标签登录 B 后，A 的下一次请求附 `Bearer synthetic-token-B`；A 的旧请求返回过期 401 时，B 的 token/user 被删除。两端现有文件在内存模拟中均复现，见 [客户端反例证据](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/evidence/audit-client-checks-2026-10-13.json)。

**应修改：** 页面与请求绑定账号、档案及会话修订号；开始、提交、响应回写都核对。账号变化通知旧标签失效，清理敏感 DOM/计时器并停止旧请求；迟到 401 只能清理自己发起时的会话。小程序已存在类似租约保护，应核对两端等价行为。

**验收：** 同源两标签进行 A→B、患者→医生、医生→医生及退出后同账号重登；旧页面不能继续提交、旧响应不能清理或回写新会话。

### R03：HGST 的“现有 Pearson 契约”实际上有两套

**方案依据：** [第 324 行](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:324) 要求复用现有 ROI、Pearson 与 Lasso；[第 377 行](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:377) 要求完整登记输入契约。复用前必须解决现有差异。

**代码事实：** 研究数据入口 [getData.py](C:/Users/Lenovo/Desktop/ADHD-AB协作版/HGST-main/src/getData.py:116) 使用 [corr.py](C:/Users/Lenovo/Desktop/ADHD-AB协作版/HGST-main/src/corr.py:29) 的 `ConnectivityMeasure(kind='correlation', standardize='zscore_sample')`。该类默认采用 Ledoit-Wolf 协方差估计；部署 [preprocessing.py](C:/Users/Lenovo/Desktop/ADHD-AB协作版/backend/app/services/hgst_runtime/preprocessing.py:82) 使用普通 `np.corrcoef`。默认估计器见 [Nilearn 官方文档](https://nilearn.github.io/0.10.3/modules/generated/nilearn.connectome.ConnectivityMeasure.html)，现场反例使用安装的 Nilearn 0.10.4。

**复现：** 同一份 16×90 合成 ROI 输入，矩阵最大绝对差 `0.8364286385`、平均绝对差 `0.1829897768`；同一 ROI 对研究结果 `0.1235222258`，部署结果 `0.9599508643`。详见 [模型与加密反例](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/evidence/audit-synthetic-checks-2026-10-13.json)。这证明变换不等价，不证明真实准确率下降多少，也不证明未读取的现有权重一定由该研究入口训练。

**应修改：** 明确每一基础编码器实际训练时的图谱、ROI 顺序/选择、相关估计器、标准化、Lasso 参数及依赖版本，把它们与权重摘要绑定。所有节点和推理端执行与该权重匹配的变换，不能凭同名 `correlation` 判断兼容。来源不清的权重标记未验证；不能随意改一边后继续宣称旧模型语义不变。

**验收：** 同一组固定合成 ROI 通过研究、节点、打包和部署得到符合规定容差的相同特征/超图/嵌入；拒绝同名但不同估计器或图谱的模型包；真实模型效果另做独立核验。

### R04：运行去重必须区分重试和同 ID 冲突

**方案依据：** [结果模型](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:433) 要求保留运行去重，[历史兼容](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:450) 禁止旧结果完成新任务，[提交验收](C:/Users/Lenovo/Desktop/ADHD-AB协作版/docs/项目升级总方案-2026-10-12.md:516) 要求只推进一次。

**代码事实：** [认知提交接口](C:/Users/Lenovo/Desktop/ADHD-AB协作版/backend/app/api/routes/patient.py:603) 按患者、任务类型、run_id 找到旧记录后立即返回，不比较新请求内容。[现有测试](C:/Users/Lenovo/Desktop/ADHD-AB协作版/backend/tests/test_cognitive_contract.py:222) 明确把第二份 accuracy 改为 1，仍返回首次 92、同一记录 ID 和成功状态。

**风险场景：** 新增 task/assessment/attempt 字段后，如果仍先按 run_id 返回旧记录，再走新任务关联，可能把任务一的证据错误绑定任务二；即便不错误绑定，也可能把冲突内容当成成功重试，掩盖客户端归属错误。这是未来集成风险，当前代码尚无这些新字段，不能称该新任务漏洞已经发生。

**应修改：** 首次提交冻结档案、任务、批次、attempt、协议和规范化内容摘要；仅完整匹配的重复请求返回原结果。同 ID 但上下文或规范化内容不同返回明确冲突，例如 409；真实重测分配新 attempt/run。摘要应基于服务端规范化结果，处理已支持的 gonogo/reaction 别名，不因等价表示制造冲突。

**验收：** 原样重试一次推进；同 run 换任务、换批次、换内容都冲突；并发同 run 只保存一次；历史结果保持原归属，不能重新贴新任务 ID。

## 7. 建议修订顺序与需要新增的规范产物

1. **先补 P0 安全与模型基线。** 明确 R01、R02、R03；复核原已承认的范围/外发/日志问题。把模型输入契约与来源匹配验证独立出来。
2. **冻结身份、任务和提交契约后再改页面。** 明确账号/儿童/监护关系、自助项与医生任务、submission/attempt/run 不可变归属、幂等冲突、离线队列和旧草稿迁移。产出字段表、唯一键/外键、状态转换与拒绝条件。
3. **固定事务与撤回行为。** 产出业务事务/outbox/关键审计时序，以及每一种活跃对象撤回后的转换表；定义 Worker 恢复和客户端状态查询。
4. **固定专业输出和比较资格。** 由专业人员确认报告类型、必要证据、量表窗口、认知条件和解释范围；“可比”要能被规则判断，并进入正反例验收。
5. **改写阶段发布矩阵并完善交付。** 每阶段列支持的客户端版本、允许开启的能力及对应安全/专业/许可条件。P2A 只延后增强，不延后已经开放能力的必要权限保证；规范性附录进入可复现交付。

这些修订保留“小程序为主、网页辅助、两类用户同步、资料选填、统一智能体、联邦先合成本机完整闭环”的方向。需要改变的是复用和验收的精确条件，以及真实使用之前的证据门槛。
