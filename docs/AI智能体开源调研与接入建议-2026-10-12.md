# AI 智能体开源调研与接入建议

调研日期：2026-10-12。范围：GitHub 仓库说明、关键源文件、依赖和许可声明，以及框架和 DeepSeek 官方文档。仅调研与设计；未克隆、安装、运行外部项目，未改业务代码或依赖。以下适配性是根据文档和静态代码作出的判断，不代表已完成兼容联调或临床验证。

## 1. 推荐选择

首期采用 **现有 FastAPI＋DeepSeek 网关＋有边界的工具执行循环＋现有数据库业务状态**。借鉴 Pydantic AI 的工具参数、依赖上下文和结构化输出设计，借鉴 LangGraph 的暂停、恢复和人工确认机制；用本项目的任务、结果和审核接口接住动作。统一智能体取代原 AI 助手入口。

这样可以保留小程序、成年／儿童量表、认知测试、消息和医生页面。引入框架是可选实现方式；评估批次、任务结果关联、医生审核和随访周期仍须建设，框架不会自动补齐这些业务能力。

若后续希望直接使用 SDK，优先评估 Pydantic AI 的精简安装；需要复杂分支、跨服务执行和检查点时再考虑 LangGraph。首期不同时引入两套框架。

## 3. 三条实现路径

| 路径 | 需要做什么 | 取舍 |
|---|---|---|
| **A：现有网关增加受限工具执行器，借鉴开源设计** | 工具注册、参数校验、权限上下文、工具结果回传、结构化输出、运行记录和回退 | **首期推荐**；依赖变化小，业务融入直接；运行控制与日志需要自行实现 |
| B：直接引入 Pydantic AI 精简包 | 包装现有服务为工具、配置 DeepSeek、接确认接口与数据库；选版本并验证 Pydantic／FastAPI 兼容 | 工具循环和类型能力可直接利用；需升级或选兼容版本，不能假定旧版本含全部当前功能 |
| C：LangGraph 编排 | 将短流程构成图节点，接持久化、审核恢复和业务事件 | 更适合复杂分支；有额外依赖、状态一致性与检查点管理，仍需业务权限和审核接口 |

无论选择哪条，界面都只有一个 AI 流程智能体入口。成年／儿童和用户／医生通过服务端上下文切换工作模式，不新增另一套助手或家长注册入口。

## 4. 当前项目需要补什么

当前 `DeepSeekClient.chat` 构造文本请求，返回 `content/model/provider`；本轮复核的 payload 没有工具定义，返回也没有暴露 `tool_calls`。已有聊天能力不能直接执行“查任务→找未完成项→打开任务→整理结果”。相关证据：[AI 服务](C:/Users/Lenovo/Desktop/ADHD-AB协作版/backend/app/services/ai_service.py:243)、[依赖](C:/Users/Lenovo/Desktop/ADHD-AB协作版/requirements.txt:9)、[AI 路由](C:/Users/Lenovo/Desktop/ADHD-AB协作版/backend/app/api/routes/ai.py)。

建议按职责增加下列模块，名称可沿用仓库规范：

| 模块／页面 | 具体调整 |
|---|---|
| AI 网关 | 接收工具 schema，保留调用 ID／参数与工具结果，支持有边界的循环；旧聊天仍兼容 |
| 智能体上下文与执行器 | 服务端确定操作者、被评估档案、成年／儿童、当前任务／周期、共享范围；限步数、超时与预算 |
| 业务工具集合 | 调用共用任务、结果和摘要服务；不得任意查询数据库或改原始作答 |
| 输出契约 | 返回解释、证据 ID、下一步白名单动作、草稿 ID、待确认状态和生成模式 |
| 运行记录 | 保存运行 ID、输入版本、业务对象、工具调用状态、授权范围、证据引用和失败原因；敏感数据继续按既有机制保护 |
| `pages/ai-chat` 与现有浮层 | 改为智能体入口；显示“继续评估／查看结果／今日记录”等按钮，按实际进度展示；测试试次不弹出 |
| 今日／评估／报告／协同页 | 接收动作卡，跳转时带任务／批次上下文；医生看到摘要草稿和确认入口 |
| 业务基础 | 评估批次、任务实际结果绑定、审核发布和独立周期与智能体同步建设 |

[DeepSeek 官方工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)说明了模型请求工具、应用执行和回传结果的机制；实际工具在项目后端执行。若启用思考模式，须按当前接口要求保留并回传 `reasoning_content`，不能继续只存纯文本；这属于内部传输处理，不展示内部思考文本。[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)

## 5. 首期工具与人工确认

| 工具／动作 | 输入与输出 | 自动化边界 |
|---|---|---|
| 查询当前任务／进度 | 服务端身份与当前批次 → 未完成任务、期限、实际状态 | 只读，按当前授权对象查询 |
| 读取本轮结果及证据 | 本轮允许的结果 ID → 系统计分、协议、来源、质量信息 | 只读，不由模型计算标准分数 |
| 给出下一步 | 实际进度＋白名单 → 页面、任务 ID、说明 | 用户点按钮进入；缺少选填背景不阻塞；没有任何背景时也可用规则入口 |
| 整理可选资料 | 用户主动提供并同意的内容 → 字段草稿及来源 | 只生成草稿，用户确认保存；跳过记为未提供 |
| 生成结果／阶段摘要 | 真实结果、系统统计、已发布意见 → 摘要草稿、证据及不足 | 不发布临床意见；结论由医生核对 |
| 后续增强：草拟计划／回复 | 已审核资料和医生要求 → 草稿 | 医生确认后由业务发布接口执行；不开放自动发布工具 |

首期建议每次智能体运行最多进行 3 次工具执行步骤，并同时限制工具总数、时间和 token 预算，超限返回现有页面与当前状态；具体数值联调后调整。写入草稿需按运行和输入版本去重。

运行时权限不能依赖提示词或客户端“已批准”标记。每个工具再次检查登录账号、patient_id 访问关系、用途同意和输入版本。模型给出的证据 ID 需确实在授权结果内，数值不得与系统计算冲突。[Pydantic AI 待确认工具说明](https://github.com/pydantic/pydantic-ai/blob/main/docs/deferred-tools.md)

## 6. 用户操作与跨环节恢复

1. 用户进入小程序，选择本人／儿童；必要年龄与填写人明确，主诉、病史和生活影响可跳过。
2. 点“下一步”或向智能体提问，后端查询实际进度，返回当前量表／测试动作卡。用户在原页面操作，系统提交并关联真实结果。
3. 提交成功触发摘要任务；智能体整理结果并标明缺失背景，用户看到解释，有关联医生则进入待审核队列。
4. 医生核对、编辑或退回，确认后发布意见和计划。智能体读取已发布版本，用户首页显示新的记录和复核任务。
5. 日常记录和计划节点触发阶段摘要；医生确认下一轮安排，智能体继续引导下一批次。

不会为整个随访周期保持一个一直运行的大模型会话。每次进入页面或业务事件触发短运行；正式进度、审核状态和日期在业务数据库中。工具执行循环负责单次动作，业务事件负责跨日接续。

如果采用 LangGraph，可用检查点及 interrupt 暂停单次待确认动作；恢复前重新核对身份、同意和数据版本。正式审核是否成立仍以 `ReviewRecord` 和发布事务为准，不以图状态取代医生审核。[LangGraph 中断与恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)

## 7. 最小验收与尚未验证项

先跑通四项：跳过选填背景仍可评估；智能体下一步与真实任务一致；结果摘要带可打开证据并进入医生审核；医生确认计划后首页出现随访任务。成年与儿童各跑一遍。

补充验证：未授权档案不可查询；工具调用不能直接完成测试或发布计划；模型失败仍能手动走流程；重试不重复建摘要和任务；过期草稿需重新核对；计时测试不被对话打断。

尚未进行依赖安装解析、真实 DeepSeek 工具联调、外部仓库运行、微信动作卡真机验证或临床评估。采用 SDK 前选定发行版本并锁定依赖；本轮核对的是调研时主分支，后续可能变化。没有把外部演示数据、出院医嘱或模型结论接入本项目。
