## 二、让新版小程序使用这一套数据

1. 微信开发者工具打开项目的 `miniprogram` 目录，编译。
2. 登录页点击“服务器连接设置”，先记住原地址。填写 **http://127.0.0.1:8770/api/v1**，测试连接并保存。
3. 返回登录页，选择“用户”或“医生”，使用上表账号和演示入口显示的密码登录。切换服务器会退出当前登录，避免串用不同库的缓存。
4. 电脑开发者工具使用本机HTTP调试；本项目现有私有配置关闭了本机开发的域名校验。不要将本机地址解释为手机或公网可访问地址。手机真机不能用127.0.0.1访问这台电脑，此方案先用于电脑录屏。
5. 恢复日常使用时，在同一设置页改回记录的原地址，并重新登录原账号。本次没有自动改动你当前微信会话或服务器设置。

## 三、如何演示完整的用户—医生流程

### 方案A：马上看完整结果、准备十张截图

小安已经通过实际业务接口完成：注册与授权 → 医生发布评估 → 量表和六项认知正式提交 → 医生逐份核对、保存私人审核并明确发布材料审核意见 → 医生发布14天计划 → 用户阅读收悉 → 实际日期记录 → 双向消息 → 星仔根据材料整理进度。

用户登录小安后依次查看：

- **评估**：第2轮，7项实际提交及医生验收状态；不是认知练习页的本地成绩。
- **沟通/意见**：医生已经发布的材料审核意见，可读取正文、局限和版本。
- **计划与记录**：专业周期1，2026-10-18至2026-10-31，今天有一条实际记录。收悉已经保存，因此收悉按钮消失；不要把重复打开页面拍成首次收悉。
- **历史自主周期2**：2026-10-05至2026-10-18，7天有记录、7天缺失；部分指标为空。这个周期独立于今日发布的专业计划，不是其历史执行结果。趋势页取景时保留周期来源。
- **沟通**：双方已经实际保存消息与回复；给医生发送新消息仍需要在实际表单确认。
- **星仔**：可直接问“练习完成为什么还不是正式完成”“现在我应该做什么”。普通问题显示解答，业务摘要读取真实保存状态。这套隔离环境没有外部模型密钥，不能宣称本段调用了DeepSeek。

医生登录后从“用户”选择小安，可读取同一轮、已发布意见、同版计划和用户实际记录；影像报告同时保留系统第1版和医生核对发布的第2版。

### 方案B：亲手录下尚未完成的交互

用小禾的第1轮评估进行实际交互，避免为了录屏撤销小安已保存的状态：

1. 用户进入**评估 → 第1轮 → 具体补问与答复**，选中已有问题，填入合成说明，如“作答时周围有人说话，我暂停后继续”，点击“核对并提交本次答复”。也可以如实选择不知道或跳过。
2. 切医生，**用户 → 小禾 → 第1轮 → 核对原始材料并进入医生审核**，点击“具体补问与实际答复”读取刚才保存的答复。
3. 在医生审核页逐份核对原提交、质量和局限，选择采纳、需新尝试或退回并说明理由。填写本人核对的正文和局限，选择允许的**材料审核意见**，点击“核对并保存私人草稿”。
4. 打开实际保存的草稿，点击“重新核对版本并确认发布”。合成评估不能发布临床诊断；材料审核意见是当前演示适用类别。
5. 进入“发布或修订医生计划”，填写合成14天观察安排，开始日期用操作当天，结束日期用之后13天。点击“核对并发布计划新版本”。不能填写过去已经执行的专业计划。
6. 切回小禾，读取医生刚发布的同轮意见与计划，点击“我已收到并阅读最新计划”，取得服务器确认；随后打开对应实际周期，保存当天记录。
7. 用户发一条合成反馈，医生从沟通入口读取并回复。再让星仔解释下一步，观察它给出的入口随实际业务状态变化。

以上是实际操作路径，做完会保存在本次演示库中，不会在刷新后自动恢复成待办。小禾的完整鼠标/微信操作录像需要按这些步骤录制；预置闭环和接口验收不等于已替你录完视频。

## 四、影像页面怎么操作

1. 从演示入口打开医生网页登录，以合成医生正常登录。进入小安的原始影像工作区：`http://127.0.0.1:8770/doctor-web/doctor_visualization.html?patient_id=2`。
2. 在入口下载**合成功能像**和**合成结构像**，在工作区的NIfTI文件框分别选择，点击载入。重启服务或更换浏览器会话后，请重新载入，不以已有摘要文字冒充已加载原始影像。
3. 看到实际切片后切换切面/时点或使用可视化控件，再按页面保存入口确认保存。第09张图拍工作区和已经加载的影像，避开文件选择器和调试器。
4. 模型分析使用入口提供的**合成ROI时间序列CSV**。它与NIfTI幻影独立生成，不能宣称已证明ROI对应关系。
5. 本次已经真实执行原HGST权重推理，保存分析1及系统报告第1版、医生审核第2版。小程序选择小安 → 影像报告，可读模型来源、90个ROI、64个时点、版本和局限。

“真实推理”表示执行了项目原有权重；输入仍是合成数据，不代表临床准确率已验证。未修改原权重，未训练新模型。

## 六、保留、重录与停用

当前合成数据目录由 `.codex-tmp/competition-demo/current.json` 记录，数据库、加密密钥、授权账本、上传和影像缓存都在该实例目录中。不要单独移动数据库而丢失同目录密钥。

需要一套全新的待办，可用启动器的 `-NewSession -Port 8771`，会创建另一套新库而保留8770演示。新入口端口是8771，小程序也必须相应改成8771。不要删除当前演示库来重置状态。

演示服务以隐藏后台进程运行。若需要停止，在 `current.json` 核对端口、项目标识和pid后，只停止这个独立演示进程；不停止8000/8767。电脑关机后重新运行启动器会复用已保存数据。

本次不包含新儿童演示账号、外部AI调用、真实微信投递、手机实机验收或联邦训练。十张图中尚未实拍的小程序画面仍需在微信开发者工具取图，不能用控制器检查代替实拍。


## 七、微信工具出现MaxCodeSize启动错误时

本机曾在页面运行前出现 `Cannot read properties of undefined (reading 'MaxCodeSize')`。错误位于开发工具内部的项目能力字段比较，账号和合成数据不依赖该字段。2026-10-18已通过当前工具的正式项目窗口接口重新建立实例s1，原生登录页截图已确认；随后再次打开实际返回reuse/s1。

在项目目录运行 `tools/open-competition-miniprogram.ps1` 可打开/复用这条已验证路径。它只打开当前项目，不改AppID、基础库、业务代码、服务器地址或账号存储。首次连接如开发工具要求授权，应由本人在工具窗口点击允许；本次Codex连接已经由用户明确允许。

恢复编译后仍须在小程序服务器设置中选择8770，再使用已准备好的合成账号登录；不要在原8000服务尝试这些演示账号。截图证据位于 `docs/evidence/wechat-maxcodesize-2026-10-18/login-recovered.png`。这次只验收到原生登录页，未把额外自动化接口的超时算为通过，也未声称已自动登录或拍好其余九图。
