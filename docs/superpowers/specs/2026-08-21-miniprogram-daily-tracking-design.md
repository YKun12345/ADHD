# 微信小程序 14 天每日追踪设计

日期：2026-08-21

## 1. 范围

对应 A 端 D8：实现原生小程序每日追踪、本地 14 天记录、离线待同步和明确标注的本地演示数据。只调用既有 `POST /patient/submit_daily_log`；不修改 B 的后端、数据库或医生端。

## 2. 核心字段

- `day_index`：1—14；默认使用首页缓存中的当前天。
- `mood_tag`：1—5 必填；同时映射到 `emotion_rating`。
- `attention_rating`：1—5 必填。
- `focus_minutes`：0—1440 的整数必填。
- `sleep_quality`：`poor/fair/good` 必填。
- `is_medication`：布尔值；为真时 `medication_dosage` 必填。
- `note`：可选，去首尾空白，最多 500 字。

表单只收集 D8 演示与纵向趋势所需字段，未填写的 B 扩展字段不伪造。

## 3. 本地与同步

`tracking_local_logs` 保存每个 day 的最近一条客观记录，按 day 覆盖并排序；`tracking_pending_logs` 保存尚未同步的 payload。提交顺序为：校验 → 本地保存 → 更新 `patient_dashboard_cache` → 请求后端。成功移除对应 pending，失败保留并显示“已保存本机，待同步”。

“生成 14 天本地演示数据”只写本地，不批量调用后端；页面和记录均标记 `demo: true` / “本地演示”，不能冒充真实患者记录或已同步数据。

## 4. 页面与入口

新增 `/pages/tracking/index`，包含 14 天进度、日期选择、情绪/注意力评分、专注分钟、睡眠、用药、备注、保存状态和演示数据入口。成人、儿童首页今日任务及快捷入口均启用；未知患者类型保持锁定。

## 5. 验收与边界

- 纯逻辑覆盖校验、payload、覆盖保存、汇总与 14 条演示数据；
- 页面覆盖加载草稿、保存成功、离线待同步、防重复、演示确认和返回；
- 视图覆盖全部字段、状态、免责声明及非仅色彩的选择状态；
- 全量测试、语法、JSON 与 Git 空白检查通过；
- 真机输入法、滚动、选择和真实接口联调留到 D13/B 恢复后验收。

页面只做记录与趋势准备，不根据单日数据提供诊断或用药建议。
