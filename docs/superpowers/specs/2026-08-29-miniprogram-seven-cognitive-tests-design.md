# 微信小程序七项认知测试完整方案设计

## 1. 目标与边界

在患者端微信小程序中提供七项原生认知任务：Go/No-Go、简单反应时、Stroop、连线、Flanker、2-back 和数字广度。系统同时提供“完整评估”和“单项测试”两种入口，根据成人/儿童患者类型自动选择参数，并把七项进度和最近结果纳入小程序本地综合报告。

本次仅修改 A 成员负责的 `miniprogram/`、相关前端自动化测试和 A 端项目文档。不修改 `backend/`、数据库、医生端网页或 B 成员的接口实现。所有结果继续调用现有 `POST /patient/submit_cognitive_test` 通用接口；接口不可用时保留本地结果和待同步状态。

这些任务提供客观行为指标和项目内纵向对比，不宣称替代标准化量表、专业访谈或医生诊断。

## 2. 方案选择

采用“独立页面 + 共享会话能力 + 独立纯逻辑模块”的原生小程序方案。

- 每项任务拥有独立页面控制器、视图和纯逻辑模块，避免形成难以维护的巨型动态页面。
- 共享模块统一处理年龄组参数、练习门槛、结果结构、数据质量、完整评估进度、本地保存和待同步队列。
- 不使用 WebView 复用网页版，因为其离线、真机触摸、计时稳定性和小程序体验均较差。
- 不把七项塞进一个页面，因为不同任务的刺激、输入、计时和恢复规则差异明显。

## 3. 七项任务

### 3.1 Go/No-Go

保留现有 `test_type: reaction` 以兼容历史数据和 B 的报告聚合。加入练习阶段、分块正式试次、刺激比例平衡、遗漏/误按/提前点击统计、反应时分布和切后台质量标记。儿童版单块更短、休息更多；成人版正式试次更多。

### 3.2 简单反应时

新增 `test_type: simple_reaction`，随机等待后显示目标，仅目标出现后点击有效。记录有效反应时、提前点击、遗漏、均值、中位数、最快/最慢反应时和反应时变异。该编号避免与现有 Go/No-Go 的 `reaction` 冲突。

### 3.3 Stroop

保留 `test_type: stroop`，加入练习门槛、相容/冲突条件平衡、颜色与位置随机化、分条件正确率和干扰效应。按钮始终显示颜色名，刺激要求判断墨水颜色。

### 3.4 连线

使用 `test_type: trail`。包含数字顺序 A 和数字/字母交替 B 两个阶段；儿童配置减少节点并使用更直观提示。记录阶段用时、总用时、错误数、纠错次数、点击路径和完成状态。

### 3.5 Flanker

使用 `test_type: flanker`。平衡一致、冲突和可选中性试次，要求判断中央箭头方向。记录总体及分条件正确率、反应时、冲突效应、遗漏和过快反应。

### 3.6 2-back

使用 `test_type: nback`。采用 3×3 空间位置刺激，练习通过后进入正式试次；目标和非目标比例受控，避免纯随机序列失衡。儿童版缩短分块并增加练习反馈，但正式任务仍保持 2-back。记录命中、漏报、虚报、正确拒绝、正确率和信号检测指标的安全近似值。

### 3.7 数字广度

使用 `test_type: digit`。包含顺背和倒背两个阶段，自适应增加长度，达到连续失败规则后结束。数字按节奏逐个呈现，作答阶段使用数字键盘。记录顺背最大跨度、倒背最大跨度、正确轮次和失败跨度。

## 4. 成人/儿童配置

页面从当前登录患者资料中读取 `patient_type`，通过纯配置模块选择 `adult` 或 `child` 参数。未知类型使用更保守的儿童参数，并在结果中记录实际配置组。

配置差异仅影响练习数量、正式试次数、单块长度、刺激时长、响应窗口、休息频率和数字跨度上限。计分字段、结果结构和测试编号保持一致，保证报告能够统一展示。

### 4.1 固定参数基线

参数采用项目内固定版本，后续调整必须提升 `schema_version`，避免不同版本结果被直接混为一谈。

| 任务 | 儿童配置 | 成人配置 | 主要平衡规则 |
| --- | --- | --- | --- |
| Go/No-Go | 10 题练习；2×40 正式试次 | 10 题练习；3×40 正式试次 | 每块 80% Go、20% No-Go；方向与位置打散 |
| 简单反应时 | 8 题练习；24 正式试次 | 8 题练习；30 正式试次 | 目标前等待 1000–2500 ms，分层打乱，避免连续可预测 |
| Stroop | 12 题练习；2×30 正式试次 | 12 题练习；3×32 正式试次 | 儿童每块 20 相容/10 冲突；成人每块 24 相容/8 冲突；颜色和按钮位置平衡 |
| 连线 | A：1–15；B：1–A 至 8–H | A：1–25；B：1–A 至 13–L | 节点位置由带最小间距的种子布局生成；A/B 各有独立练习 |
| Flanker | 12 题练习；48 正式试次 | 12 题练习；2×48 正式试次 | 相容、冲突、中性各占 1/3；目标左右各半 |
| 2-back | 10 题练习；45 正式试次 | 10 题练习；2×45 正式试次 | 目标约占 1/3；避免连续三次同位；位置分布近似均衡 |
| 数字广度 | 顺背/倒背各 3–8 位，每长度 2 轮 | 顺背/倒背各 3–9 位，每长度 2 轮 | 相邻数字不重复；所有长度完成，不因早期失败提前终止 |

练习门槛默认为最近一组达到 75% 正确率；最多提供三次带反馈练习。三次仍未通过时允许继续正式测试，但必须写入 `practice_not_passed` 质量标记。正式试次不提供对错反馈，避免反馈改变后续作答策略。

预计完整评估净任务时间为儿童 30–40 分钟、成人 40–50 分钟，另加可选休息时间。完整模式在每个正式分块之间提供休息，不强制患者连续完成全部七项。

### 4.2 参数依据与限制

- Go/No-Go 的 80:20 比例、300 ms 刺激和约 1500 ms 试次节奏参考儿童 ADHD 研究中的计算机任务设置。
- Stroop 使用混合相容/冲突试次并分别报告中位反应时和正确率，避免只使用单一冲突区块。
- Flanker 保留相容、冲突和中性条件，并对方向和条件做平衡。
- 2-back 保留练习与足够正式试次；儿童研究中已有 10 题练习加 45 个计分试次的实现。
- 数字广度包含顺背与倒背，并完成所有预设长度；儿童 ADHD 研究提示，简单的提前终止规则可能削弱倒背任务的构念效度。

这些文献只能支持范式和参数选择，不能替代对本小程序版本的信度、效度、常模和设备计时误差验证。

## 5. 双模式流程

认知中心提供两个入口：

1. 完整评估：按 Go/No-Go、简单反应时、Stroop、连线、Flanker、2-back、数字广度的固定顺序完成。每项完成后保存进度并显示休息页，可退出后从下一项继续。
2. 单项测试：从七张任务卡进入任意项目，可查看最近摘要或重新测试。

为了保护数据质量，进行中的单个试次块不跨应用重启恢复。切后台或退出会标记本块中断；返回后从练习或当前正式分块开头重做。已完成项目不会丢失。

## 6. 数据模型与同步

每项完成后生成统一 payload：

```js
{
  test_type: 'flanker',
  result_json: {
    schema_version: 2,
    test_name: 'Flanker 任务',
    status_text: '已完成',
    age_group: 'adult',
    mode: 'battery',
    summary: '已完成正式测试',
    metrics: [{ label: '正确率', value: '86%' }],
    raw_result: {},
    quality: {
      valid: true,
      flags: [],
      interrupted_count: 0,
      practice_attempts: 1
    },
    trials: [],
    finished_at: 'ISO-8601'
  }
}
```

`trials` 只保存刺激条件、作答、正确性、反应时和必要的序号，不重复保存姓名、邮箱、令牌等身份数据。最近结果写入现有 `cognitive_latest_results`，扩展为七个键；完整评估状态使用独立本地键并按当前患者会话隔离。

每项先保存本地结果，再调用现有通用接口。失败时写入统一待同步队列；再次进入认知中心或网络恢复后逐条重试。重试成功只更新同步状态，不改变客观结果。

## 7. 认知中心与报告

认知中心显示七项进度、完整评估入口、预计剩余时间、最近完成状态和单项关键指标。任务卡只展示客观结果，不给出疾病诊断结论。

小程序本地报告把认知任务总数从 2 扩展为 7，展示每项最近指标和数据质量状态。服务端报告仍然优先；若服务端未返回 `simple_reaction`，本地最近结果用于补充该卡片。A 端不修改服务端雷达算法，也不伪造服务端已接收或已聚合的状态。

## 8. 计时、生命周期与异常处理

- 反应时使用 `Date.now()` 的单调差值约束，结果取非负整数。
- 页面维护的所有定时器必须集中登记，在隐藏、卸载、重开和完成时清理。
- 作答锁防止同一试次重复点击；刺激切换后才解除。
- `onHide` 记录中断并停止当前块；不把后台停留时间计入反应时。
- 过快反应、连续固定位置作答、高遗漏率、中断和练习多次失败形成质量标记，不直接给出医学判断。
- 本地存储异常时仍展示当次结果，并明确提示“未保存”；接口失败不得显示“已同步”。

## 9. 文件结构

新增五个页面：

- `miniprogram/pages/simple-reaction/`
- `miniprogram/pages/trail/`
- `miniprogram/pages/flanker/`
- `miniprogram/pages/nback/`
- `miniprogram/pages/digit-span/`

新增对应纯逻辑模块，并增加共享的参数、会话、结果和完整评估状态模块。现有 `pages/cognitive/` 与 `pages/stroop/` 保持路由兼容，在原结构内升级流程。`cognitive-results.js` 和 `report-data.js` 扩展为七项定义。

## 10. 测试与验收

所有生产逻辑按测试驱动方式实现：先添加会失败的测试，再写最小实现并回归。

- 纯逻辑测试覆盖成人/儿童配置、试次生成、判定、计分、质量标记和 payload。
- 页面控制器测试覆盖开始、练习、正式分块、重复操作保护、中断、保存、同步失败和重试。
- 视图测试覆盖说明、进度、刺激、作答控件、结果、免责声明、七项入口和无障碍文本。
- 汇总与报告测试覆盖 0/7、部分完成、7/7、旧两项缓存迁移和服务端/本地合并。
- 全量 Node 测试、JavaScript 语法检查、JSON 解析和 Git 空白检查必须通过。
- 最终提供微信开发者工具与成人/儿童真机验收清单；无法由本地自动化替代的触摸节奏、字体、振动和前后台切换明确列为外部验收。

## 11. 完成标准

- 七项均可从认知中心独立完成并产生可信的客观摘要。
- 完整评估可按顺序运行、在项目之间退出并继续。
- 成人/儿童配置自动生效且记录在结果中。
- 七项结果均先本地保存，并通过现有接口同步或明确进入待同步状态。
- 小程序本地报告和认知中心一致显示七项进度与最近结果。
- 不修改 B 负责的任何文件。
- 不宣称测试结果能够独立诊断 ADHD。
