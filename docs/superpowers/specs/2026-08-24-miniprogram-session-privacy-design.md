# 微信小程序会话与本地数据隐私设计

日期：2026-08-24

## 目标

在不依赖 B 后端新增接口的前提下，为患者小程序补齐统一会话保护、退出账号和本地患者数据清理。受保护页面不得在 token 或患者资料缺失时继续读取或展示患者数据；不同使用者不得通过退出后重新登录看到前一个患者遗留的本地记录。

本功能只修改 A 的原生微信小程序，不修改 `backend/`、医生 Web、PPT、汇报或录屏材料。

## 范围

本次实现：

1. 统一验证 `access_token` 与 `current_user`；
2. 登录、注册和服务器设置保持公开；
3. 其余正式业务页面统一注册为患者受保护页面；
4. 首页增加“账号与隐私”入口；
5. 新增账号与隐私页面，显示患者名称、本地数据摘要和待同步提示；
6. 二次确认后清除本地患者数据；
7. 二次确认后退出账号，并同时清除患者本地数据；
8. 服务器地址 `api_base_url` 始终保留。

本次不实现：

- 离线同步中心；
- 微信订阅提醒；
- 独立网络诊断页面；
- 修改密码、找回密码或注销后端账号；
- 删除后端已经保存的数据。

## 方案选择

采用“集中会话模块 + 患者页面包装器 + 独立账号与隐私页”。

没有采用首页直接放置危险按钮，因为退出和删除需要完整说明及二次确认；没有采用按账号迁移全部缓存，因为当前缓存没有稳定的账号命名空间，迁移范围大且容易破坏已验证的量表、认知和追踪流程。

## 架构

### `utils/session-privacy.js`

纯逻辑和微信存储适配集中在一个模块，负责：

- 定义会话键和患者数据键白名单；
- 判断 token 是否为非空字符串、用户是否为有效对象；
- 汇总草稿、结果、追踪记录和待同步项目数量；
- 逐项删除患者数据，禁止使用 `wx.clearStorageSync()`；
- 清除会话并更新 `app.globalData.isLoggedIn`；
- 会话失效时返回登录页。

### `utils/patient-page.js`

提供 `registerPatientPage(definition)`。它在原页面 `onLoad` 和 `onShow` 之前验证会话：

- 会话有效时调用原生命周期并保持原返回值；
- 会话无效时不调用原生命周期，清除残缺会话和患者本地数据，并 `wx.reLaunch` 到登录页；
- 防止同一页面生命周期连续触发多次跳转；
- 不改变页面已有的业务方法和 `this`。

登录、注册和服务器设置继续直接使用 `Page()`。首页、量表、认知中心、Go/No-Go、Stroop、追踪、趋势、综合报告、AI 助手、临床路径、科普列表、科普详情以及账号与隐私页使用患者页面包装器。

### `pages/privacy-settings/`

页面包含：

- 当前患者名称；
- 本地草稿数量；
- 本地结果数量；
- 追踪记录天数；
- 待同步项目数量；
- “清除本地患者数据”按钮；
- “退出账号”按钮；
- 本地删除不影响服务器已保存数据的说明；
- 医疗免责声明。

首页底部与服务器设置入口并列提供“账号与隐私”入口。

## 数据边界

### 清除的会话键

- `access_token`
- `current_user`

### 清除的患者数据键

- `patient_dashboard_cache`
- `scale_draft_asrs`
- `scale_draft_snap_iv`
- `scale_latest_result`
- `cognitive_latest_results`
- `pending_cognitive_result`
- `pending_stroop_result`
- `tracking_local_logs`
- `tracking_pending_logs`

### 必须保留的设备配置

- `api_base_url`
- 微信开发者工具项目配置和私有配置

不得记录或输出 token、完整患者资料、完整量表答案或完整追踪请求体。

## 行为规则

### 会话失效

token 与患者资料必须同时存在。任一缺失、类型错误或内容为空时：

1. 不运行受保护页面的原生命周期；
2. 删除会话键和患者数据键；
3. 将全局登录状态设为 `false`；
4. 重新启动到 `/pages/login/index`。

### 清除本地患者数据

1. 显示二次确认，明确列出本地删除范围；
2. 用户取消时不删除任何键；
3. 用户确认后只删除患者数据键；
4. 当前 token、用户资料和服务器地址保留；
5. 页面摘要立即归零，并提示服务器数据不受影响。

### 退出账号

1. 显示二次确认，特别提示未同步数据将无法恢复；
2. 用户取消时保持当前状态；
3. 用户确认后删除患者数据键和会话键；
4. 服务器地址保留；
5. 全局登录状态设为 `false`；
6. 使用 `wx.reLaunch` 返回登录页，避免返回按钮重新进入患者页面。

### 请求收到 401

请求层复用统一退出清理逻辑，清除会话和患者本地数据后返回登录页。错误对象仍保留原状态码和后端中文信息，不吞掉调用方错误处理。

## 异常与防误操作

- 删除和退出均使用 `wx.showModal`，不能依赖单次点击直接执行；
- 操作进行中忽略重复点击；
- 只使用明确白名单逐项删除，绝不清空整个 storage；
- storage 中不存在某个键时仍视为成功；
- 页面摘要只显示数量，不显示完整敏感内容；
- 服务器地址不会因退出、清理或 401 被删除。

## 测试与验收

严格先测试后实现：

1. 会话模块覆盖有效、缺 token、缺用户、错误类型和空字符串；
2. 数据摘要覆盖草稿、结果、追踪数组、追踪待同步对象和认知待同步结果；
3. 白名单删除验证患者键被删除、服务器地址保留；
4. 页面包装器验证有效会话调用原生命周期，无效会话阻断并只跳转一次；
5. 静态测试确认所有受保护正式页面使用包装器，三个公开页面不使用；
6. 账号与隐私页覆盖取消、确认、重复点击、摘要刷新和退出跳转；
7. 视图测试覆盖警示文字、二次确认入口、医疗提示和首页入口；
8. 请求层 401 回归验证统一清理；
9. 全量 Node 测试、所有 JavaScript 语法、JSON 解析、路由、WXML 事件和 Git 边界检查全部通过；
10. 用户未提交的 `miniprogram/utils/register-validation.js` 哈希保持不变。

## 完成标准

- 任一受保护页面不能在残缺会话下读取患者本地数据；
- 清理和退出都必须经过确认；
- 不同患者不会通过退出后重新登录继承前一个患者的本地记录；
- `api_base_url` 在全部清理场景保持不变；
- 不修改 B 职责文件，不虚报删除服务器数据；
- 自动测试及微信开发者工具编译检查通过后，功能才可记为完成。
