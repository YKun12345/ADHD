# 微信小程序 SNAP-IV 与通用量表体验设计

日期：2026-08-21

## 1. 目标

本子项目对应 A 端 D5：在已经完成的 ASRS 单题页面中加入 SNAP-IV 26 题儿童量表，按患者类型自动选择正确题库，并统一成人/儿童的草稿、进度、提交和结果展示体验。

## 2. 范围边界

A 负责题库迁移、移动交互、草稿、payload、请求、结果视图和首页入口。B 负责服务端算分；本阶段不修改 `backend/`，也不在前端生成医学风险结论。

SNAP-IV 当前默认由家长代填，请求使用 `respondent_type: 'parent'`；ASRS 保持 `self`。

## 3. 方案

- 复制一套儿童页面：速度快但长期产生两套控制器，不采用。
- 在现有 ASRS 文件中堆叠大量 `if`：改动少但边界混乱，不采用。
- 通用量表会话 + 两份独立配置（采用）：页面只面向统一模型，成人和儿童配置分别声明题目、选项、草稿键和 payload 字段。

## 4. 文件结构

- `utils/scale-session.js`：通用答案清洗、不可变更新、题目状态和 payload 构造。
- `utils/asrs-scale.js`：保留现有公开 API，内部使用通用会话。
- `utils/snap-scale.js`：26 题、四级选项、家长代填配置和绑定后的会话 API。
- `pages/scale/index.js`：根据 `patient_type` 选择 ASRS 或 SNAP-IV，不再把儿童视为不支持。
- 既有量表 WXML/WXSS：标题、说明、选项数和结果均由配置驱动。

## 5. 行为规则

- 成人：18 题，0—4，从不/很少/有时/经常/非常频繁，草稿键 `scale_draft_asrs`。
- 儿童：26 题，0—3，从不/偶尔/经常/非常频繁，草稿键 `scale_draft_snap_iv`。
- 页面从 `current_user.patient_profile.patient_type` 自动选择，未知类型显示安全提示。
- 草稿仅接受从第 1 题开始连续有效的整数答案；首个非法值后全部丢弃。
- 最后一题完整后请求 `/patient/submit_scale`；失败保留相应量表草稿。
- 成功结果的 `low/medium/high` 只做中文显示映射，不改变后端结论。
- 成人和儿童首页行为量表入口均启用；其他模块仍锁定。

## 6. 验证

- 保留全部 ASRS 测试并在抽取通用会话后继续通过；
- 新增 SNAP 题数、选项、草稿、payload 和边界测试；
- 页面测试覆盖成人与儿童配置、两个草稿键、两个 payload、错误恢复和结果中文标签；
- 首页测试覆盖儿童入口已启用；
- 全量 Node、JavaScript 语法和 Git 空白检查通过。

## 7. 自审

- SNAP 26 题与现有 Web 版逐项一致；
- 成人/儿童不会串用草稿或 respondent type；
- 通用会话不访问 `wx`；
- 不替 B 实现算分，不伪造服务端结果；
- 未引入 D6 认知测试范围；
- 无未定义占位内容。
