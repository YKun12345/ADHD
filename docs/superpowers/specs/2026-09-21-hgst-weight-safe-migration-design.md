# HGST 权重安全迁移设计

## 目标

将旧源码中的 HGST 部署权重安全复制到当前 ADHD-AB 协作版预设的模型目录，使当前后端能够发现该权重，同时不迁移旧后端、不改变现有网页或小程序行为，也不将演示结果标记为真实结果。

## 来源与目标

- 来源：相邻旧源码工作区中的 `backend/artifacts/hgst_adhd_bundle.pt`
- 目标：当前项目中的 `backend/models/hgst_adhd_bundle.pt`
- 来源文件大小：`59,203,363` 字节
- 来源 SHA-256：`74575AFA48EF423461CA463F8C57CC2F1B767C3CF320C94367C00E02ABA7F95A`

## 迁移边界

本次只复制 HGST 部署权重。不会复制旧源码的后端、配置、数据库、依赖环境或存在语法错误的安全服务代码；不会修改患者网页、医生网页、小程序、AI 服务商配置或数据库结构。

当前项目继续使用已有的 `real`、`mock`、`auto` 推理模式。迁移权重不会自动启用 Mock，不会把 Mock 结果改成真实结果，也不会绕过真实推理的依赖检查。

## 安全与可恢复性

目标文件当前不存在，因此迁移不会覆盖已有模型。复制后必须重新计算目标文件的大小和 SHA-256，只有与来源完全一致才视为成功。还要以只读方式检查 PyTorch ZIP 容器中是否存在编码器、分类器和配置相关条目。

权重文件继续遵循项目现有的 `*.pt` 忽略规则，不提交到 Git，避免大型医疗模型二进制进入普通源码历史。项目中的模型说明文件记录来源、目标、哈希以及恢复方式。

如验证失败，只删除本次新建且哈希不匹配的目标文件；不得修改或删除来源文件。

## 验证标准

1. 当前配置解析出的默认权重路径等于目标路径。
2. 目标文件存在，大小为 `59,203,363` 字节。
3. 来源与目标 SHA-256 完全相同。
4. 权重容器含有 `encoder_state_dict`、`classifier_state_dict` 和 `classifier_input_dim` 标识。
5. 现有 Mock 模型校验仍能通过。
6. 默认真实模式能发现权重；若仍因本机只有 Python 3.11、缺少 `torch`/`dhg` 而停止，应明确报告为运行环境未就绪，不能宣称真实推理已经打通。

## 不在本次范围内

- 安装 Python 3.10、PyTorch 1.13.1 或 DHG 0.9.5。
- 使用患者数据进行真实预测。
- 重新训练、微调或评估模型准确率。
- 将 `.1D`/`.csv` 推理链路改为直接处理 NIfTI/GIfTI。
- 将权重上传到 Git 或任何外部服务。
