# 微信小程序 AI 助手聊天 UI 设计

日期：2026-08-21

## 1. 目标

在不修改 B 端代码、不伪造大模型结果的前提下，为成人和儿童患者账号增加原生微信小程序 AI 助手页面。页面对接现有只读契约 `POST /api/v1/ai/chat`，支持综合问答、报告解读和追踪建议三种上下文，并在接口不可用时保留当前会话和失败重试能力。

D11 只完成 A 负责的患者端聊天 UI、请求编排、输入校验、会话展示、降级状态与安全提示。模型配置、提示词、患者快照、聊天日志入库和医学内容审核仍属于 B 的职责。

## 2. 已确认边界

允许修改：

- `miniprogram/` 中患者端页面、纯逻辑、路由、首页入口和测试；
- D11 设计、实施计划、进度与工作日志。

不得修改：

- `backend/` 的 AI 路由、模型服务、数据库和环境变量；
- 医生端 AI 日志页面；
- 千问 API Key、模型名称、提示词或服务部署；
- D12 科普与临床路径、D14 精细美化、D16/D17 PPT。

安全约束：

- 不在小程序本地 storage 持久化聊天正文；
- 不把 token、密码、完整报告或完整医疗资料写入 Console；
- 不在接口失败时生成本地“AI 答案”；
- 不把静态欢迎语描述为模型回复；
- 页面始终显示“AI 内容仅用于健康教育和追踪辅助，不能替代医生诊断或处方建议”；
- 儿童患者显示监护人陪同使用提示；
- 不使用 `rich-text` 渲染服务端 Markdown/HTML，只按纯文本展示，降低注入风险。

## 3. 方案比较

### 方案 A：纯服务端聊天

页面只负责发送文本并显示结果。实现最少，但离线时用户消息容易丢失，也无法清楚区分发送中、失败和可重试状态。

### 方案 B：服务端聊天 + 本地模板回答

接口失败时返回预置回答，演示连续性较好，但容易让用户误认为模板内容来自 AI 或患者数据，并可能形成未经审核的医学建议，因此不采用。

### 方案 C：服务端聊天 + 当前会话状态机 + 明确失败重试（采用）

聊天回答只来自真实接口。页面在内存中保留本次打开期间的消息，展示发送中、已发送、降级回答和发送失败状态；失败消息可重试，但不自动生成答案。这样既满足演示与交互完整性，也保持 A/B 边界和医疗安全。

## 4. 接口契约

只读复用现有契约：

```http
POST /api/v1/ai/chat
Authorization: Bearer <token>
Content-Type: application/json
```

请求：

```json
{
  "message": "请帮我理解最近的量表结果",
  "conversation": [
    { "role": "user", "content": "上一条问题" },
    { "role": "assistant", "content": "上一条回答" }
  ],
  "context_scope": "report"
}
```

规则：

- `message` 去除首尾空白后长度为 `1—4000`；
- `context_scope` 只允许 `general`、`report`、`tracking`；
- 只携带最近 6 条已完成的用户/助手消息；
- 欢迎引导、发送中、发送失败、错误文本和本地 UI 字段不进入 `conversation`；
- 当前待发送消息只出现在 `message`，不重复放进 `conversation`。

响应：

```json
{
  "reply": "纯文本回答",
  "model": "模型或降级标识",
  "provider": "qwen",
  "disclaimer": "安全说明",
  "used_context": ["量表", "追踪"],
  "degraded": false
}
```

只有非空 `reply` 才视为成功。其他字段均按安全默认值标准化：未知 provider 不直接作为可信品牌宣传；`used_context` 只接受非空字符串；缺少 disclaimer 时使用前端固定医疗提示；`degraded: true` 显示“安全降级回答”，不显示为完整模型能力。

## 5. 纯逻辑模型

新增 `miniprogram/utils/ai-chat.js`，不访问 `wx`，导出：

- `MAX_MESSAGE_LENGTH`：4000；
- `DEFAULT_DISCLAIMER`：固定安全说明；
- `CHAT_CONTEXTS`：三个白名单上下文及中文标签；
- `validateChatMessage(value)`：返回标准化文本和错误；
- `normalizeContextScope(value)`：非法值回退 `general`；
- `buildConversation(messages, limit)`：过滤并裁剪可发送历史；
- `buildChatPayload({message, messages, contextScope})`：生成后端 snake_case 请求；
- `normalizeChatResponse(payload)`：返回稳定助手消息元数据或 `null`；
- `createGuideMessage(patientType)`：生成不参与接口历史的静态使用引导；
- `buildSuggestions(patientType)`：成人/儿童安全快捷问题。

消息模型：

```js
{
  id: '唯一页面内 ID',
  role: 'guide|user|assistant',
  content: '纯文本',
  status: 'sent|sending|failed',
  degraded: false,
  usedContext: [],
  disclaimer: ''
}
```

`guide` 永远不发送给后端。用户失败消息只有在明确点击重试后才重新发送。

## 6. 页面状态与交互

新增 `pages/ai-chat/index`：

- `onLoad(options)` 读取 `current_user.patient_profile.patient_type`，建立成人或儿童欢迎引导；如果路由参数 `scope` 合法，则使用该上下文；
- 输入使用受控 `textarea`，实时显示字符数；空白或超过 4000 字时不发请求并给出明确提示；
- 点击建议只填入输入框，不自动发送，避免意外提交；
- 点击发送后立即追加用户气泡，清空输入并进入 `sending`；
- `sending` 期间重复点击不发第二个请求；
- 成功后把用户消息标为 `sent`，追加助手纯文本气泡，并记录降级、引用范围和免责声明；
- 失败后保留用户气泡并标为 `failed`，显示“重新发送”；
- 重试使用同一文本和当前上下文，不重复堆叠相同用户气泡；
- 每次消息变化后更新 `scrollIntoView` 到底部锚点；
- “清空本次对话”只清除页面内存并恢复欢迎引导，不删除服务端日志；
- 返回按钮使用 `navigateBack`。

页面不自动读取 `/patient/ai_logs`，原因是 D11 的最小可靠闭环是当前会话；服务端历史的权限、分页和删除策略属于后续真实联调，不在 A 端自行推断。

## 7. 首页入口

在 `home-dashboard` 中新增 AI 可用性：

- 成人和儿童：`available: true`、`statusLabel: '开始咨询'`、`url: '/pages/ai-chat/index'`；
- 未知患者类型：保持不可用；
- 只加入“快捷入口”，不把 AI 问答伪装成每日必做筛查任务；
- `app.json` 登记 `pages/ai-chat/index`。

首页现有双列快捷网格可以容纳第五项，最后一项自然左对齐，不需要 D14 级视觉重构。

## 8. 视图结构

页面从上到下为：

1. 返回、标题和“清空本次对话”；
2. 医疗安全提示，儿童额外显示监护人提示；
3. 三个上下文切换项；
4. 可滚动消息区；
5. 空会话快捷问题；
6. 固定输入区、字符数和发送按钮；
7. 当前回答来源、降级状态、引用范围和免责声明。

消息使用普通 `<text>` 并设置 `user-select`，不使用 HTML 或 Markdown 渲染。按钮统一 flex 水平、垂直居中，规避之前出现的文字基线偏移问题。

## 9. 错误与异常状态

- 网络失败/超时：保留失败消息，显示轻量错误和重试按钮；
- 401：沿用 `request.js` 清会话并回登录页；
- 4xx/5xx：显示后端 detail 的通用错误，不泄露请求正文；
- 响应为空或结构非法：按“服务返回内容不完整，请稍后重试”处理；
- 快速重复点击：只产生一个请求；
- 页面离开时仍有异步返回：用页面活动标记避免离开后继续 `setData`；
- 超长消息：不截断后偷偷发送，明确提示 4000 字限制；
- 接口降级：正常显示回答，但增加“安全降级回答”标签。

## 10. 测试与验收

先测试、再实现、再验证：

- 纯逻辑：空白、边界长度、超长、非法上下文、历史过滤/裁剪、请求字段、合法/非法响应、成人/儿童引导；
- 页面控制：初始化、输入、建议、上下文、成功、降级、失败、重试、防重复、清空、返回、页面卸载；
- 入口：成人、儿童和未知类型、路由登记；
- 视图：消息滚动、三类气泡、失败重试、上下文、建议、textarea、发送按钮、安全提示；
- 全量：所有 Node 测试、全部 JavaScript 语法、JSON 解析和 `git diff --check`。

微信开发者工具与真实 AI 接口的人工发送效果、键盘顶起和真机滚动属于 D13 外部验收，不妨碍 D11 自动化代码闭环，但必须记录为待验收而不是虚报完成。

## 11. 完成标准

- 成人和儿童首页均能进入 AI 助手；
- 合法文本可按真实契约发送并展示纯文本回答；
- 上下文、最近历史、降级、引用范围和免责声明准确；
- 离线失败可重试且没有本地伪造回答；
- 聊天正文不写入小程序 storage 或 Console；
- 不修改任何 B 端文件；
- 自动测试与静态检查全部通过；
- D11 进度、证据、风险和工作日志已更新。
