# 微信小程序患者注册功能设计

日期：2026-08-20
状态：已获用户确认并通过自检，等待规格文件复核

## 1. 背景

当前原生微信小程序已经具备患者登录页、患者首页、统一请求封装和本地 token 存储方式。患者注册路由已经加入 `app.json`，登录页也已经能够跳转到注册页，但注册页仍是占位结构。

后端已有 `POST /api/v1/auth/register` 接口和患者注册数据模型，但本轮尚未启动并完成真实接口验证。因此本设计先保证小程序字段、校验、请求结构和成功状态与现有后端代码一致；真实端到端联调在后端可用后执行。

## 2. 目标

实现一个可滚动、可校验、可提交的患者注册页，使成人和儿童患者能够使用邮箱及密码创建账号。注册成功后小程序保存后端返回的登录凭证，并直接进入患者首页。

完成后的流程为：

```text
登录页进入注册页
→ 填写患者信息和账号信息
→ 阅读并勾选知情同意
→ 本地校验
→ 调用注册接口
→ 保存 token 和用户资料
→ 进入患者首页
```

## 3. 范围

### 3.1 本次实现

- 成人与儿童共用一个患者注册页；
- 患者姓名、患者类型、年龄和可选性别；
- 邮箱、密码、确认密码；
- 密码显示与隐藏；
- 密码安全规则提示；
- 知情同意勾选和说明弹窗；
- 表单校验、请求数据转换和注册请求；
- 重复提交保护、错误提示和失败后表单保留；
- 注册成功后的 token、用户资料和全局登录状态更新；
- 自动进入患者首页；
- 返回登录页入口；
- 自动化校验测试、请求数据转换测试和微信开发者工具手工验证。

### 3.2 本次不实现

- 邮箱验证码；
- 找回密码；
- 注销账号；
- 儿童监护人资料；
- 正式的知情同意版本、签署时间、到期时间和撤回流程；
- 自动根据年龄判定患者类型；
- 后端不支持的手机号、用户名或其他注册字段。

上述内容不得以不可用按钮或虚假成功状态出现在当前页面中。

## 4. 视觉与布局

采用已经确认的“B：分区单页”方案，继续使用登录页和患者首页已有的视觉语言：

- 页面背景为浅灰蓝；
- 主色为深蓝 `#17324D`；
- 辅助色为青绿色；
- 输入内容使用白色卡片和浅灰输入框；
- 圆角、阴影、字号和间距与登录页保持一致；
- 页面允许纵向滚动，不通过缩小字体强行塞进一屏。

页面自上而下包含：

1. “创建患者账号”标题和 14 天辅助筛查说明；
2. “患者信息”卡片；
3. “账号安全”卡片；
4. 知情同意勾选项；
5. “创建账号并登录”主按钮；
6. “已有账号，返回登录”入口；
7. 辅助筛查免责声明。

## 5. 字段设计

| 页面字段 | 页面状态字段 | 是否必填 | 后端字段 | 规则或转换 |
| --- | --- | --- | --- | --- |
| 患者姓名 | `fullName` | 是 | `full_name` | 去除首尾空格，长度 2～100 |
| 患者类型 | `patientType` | 是 | `patient_profile.patient_type` | 仅允许 `adult` 或 `child`，不设置默认值 |
| 年龄 | `age` | 是 | `patient_profile.age` | 数字键盘输入，转换为 1～120 的整数 |
| 性别 | `gender` | 否 | `patient_profile.gender` | 未选择时发送 `null` |
| 邮箱 | `email` | 是 | `email` | 去除首尾空格并转为小写，检查基本邮箱格式 |
| 密码 | `password` | 是 | `password` | 8～128 位，不能为纯数字或常见弱密码 |
| 确认密码 | `confirmPassword` | 是 | 不发送 | 必须与密码一致 |
| 知情同意 | `consentAgreed` | 是 | `consent_agreed` | 必须为 `true` |

性别选择值定义为：

- 男：`male`；
- 女：`female`；
- 其他：`other`；
- 不愿透露：`undisclosed`；
- 未选择：`null`。

患者类型决定后续量表和任务内容。现有后端没有提供年龄与患者类型的一致性规则，因此本轮要求用户主动选择，但不擅自根据年龄推导或阻止提交。

## 6. 密码规则

前端规则必须与 `backend/app/core/password_policy.py` 当前规则保持一致：

- 长度不少于 8 位；
- 长度不超过后端模型允许的 128 位；
- 不能为纯数字；
- 不能使用后端列出的常见弱密码。

前端校验用于即时反馈，后端仍是最终安全规则来源。后端拒绝密码时，小程序显示后端返回的安全提示，不把前端校验当作安全边界。

当前 `utils/register-validation.js` 的姓名长度、密码最大长度和弱密码集合尚未完全对齐后端，实施时必须先补充失败测试，再修改实现。

## 7. 知情同意设计

注册页显示未默认勾选的知情同意选项。点击说明文字打开弹窗摘要，至少说明：

- 会收集账号资料、患者基础资料、量表、认知测试和追踪数据；
- 数据用于辅助筛查、任务安排和报告生成；
- 平台结果不替代专业医生诊断；
- 当前竞赛版本的正式文本仍需指导老师或相关专业人员审核。

现有注册接口只保存 `consent_agreed` 布尔值，不能宣称已经具备正式协议版本、签署时间、到期和撤回记录。页面文案必须与这一实际能力一致。

## 8. 文件与职责

### `pages/register/index.wxml`

负责页面结构、表单控件、患者类型选择、性别选择、知情同意入口、按钮和免责声明。

### `pages/register/index.wxss`

负责分区单页布局、卡片、输入框、选中状态、密码提示、按钮状态和移动端滚动样式。

### `pages/register/index.js`

负责页面状态、输入事件、密码可见状态、弹窗、调用校验、调用数据转换、发送请求、保存成功状态和页面跳转。

页面状态至少包括：

- `fullName`；
- `email`；
- `patientType`；
- `age`；
- `gender`；
- `password`；
- `confirmPassword`；
- `consentAgreed`；
- `showPassword`；
- `showConfirmPassword`；
- `submitting`。

### `utils/register-validation.js`

只负责纯表单校验并返回第一条用户可理解的中文错误，不访问 `wx`、页面实例或网络。

### `utils/register-payload.js`

只负责把已经通过校验的页面状态转换为后端注册数据。该模块不得包含页面跳转或网络请求。

### `utils/request.js`

继续负责基础 URL、JSON 请求、超时、HTTP 状态和网络失败。注册页只处理注册业务相关的错误翻译。

## 9. 请求数据

`utils/register-payload.js` 生成以下数据：

```js
{
  email: 'patient@example.com',
  password: 'BrainMap#2026',
  full_name: '张三',
  role: 'patient',
  consent_agreed: true,
  patient_profile: {
    age: 20,
    gender: 'female',
    patient_type: 'adult'
  }
}
```

不得发送 `confirmPassword`、`showPassword`、`showConfirmPassword` 或 `submitting`。

请求配置为：

```text
POST /api/v1/auth/register
Content-Type: application/json
```

## 10. 提交流程

1. 如果 `submitting` 为 `true`，直接忽略重复点击；
2. 调用 `validateRegistration`；
3. 如果校验失败，显示第一条错误并停止，不发送请求；
4. 把 `submitting` 设置为 `true`；
5. 使用 `buildRegistrationPayload` 生成请求数据；
6. 调用统一 `request` 方法发送注册请求；
7. 检查响应同时包含 `access_token` 和 `user`；
8. 保存 `access_token` 与 `current_user`；
9. 更新 `getApp().globalData.isLoggedIn` 和 `userInfo`；
10. 显示“注册成功”，随后使用 `wx.reLaunch` 进入 `/pages/home/index`；
11. 注册失败时恢复 `submitting`；注册成功后保持提交锁定，直到 `wx.reLaunch` 完成页面切换。

注册失败时保留所有表单字段，便于用户修正。页面不得把密码、token 或完整注册请求写入控制台。

## 11. 错误处理

页面至少处理以下情况：

| 情况 | 用户提示或行为 |
| --- | --- |
| 本地字段校验失败 | 显示对应中文提示，不发送请求 |
| 邮箱已经注册 | “该邮箱已经注册，请直接登录” |
| 后端密码策略拒绝 | 显示后端安全提示或对应中文提示 |
| FastAPI 字段校验错误 | “填写信息格式不正确，请检查后重试” |
| 网络失败或后端未启动 | 使用统一请求层的连接失败提示 |
| 请求超时 | 提示检查网络或后端服务 |
| 响应缺少 token 或 user | “服务器未返回完整登录信息” |
| 重复点击 | 忽略后续点击，按钮保持加载和禁用状态 |

未知错误使用“注册失败，请稍后重试”，不向用户展示堆栈或内部异常对象。

## 12. 导航与状态

- 登录页通过 `wx.navigateTo` 打开注册页；
- 注册页的“返回登录”优先使用 `wx.navigateBack`，没有上一页时再跳转登录页；
- 注册成功使用 `wx.reLaunch` 清理注册和登录页面历史；
- 注册失败不离开当前页；
- 密码只存在当前页面内存中，离开页面后不写入本地存储；
- token 和用户资料只在后端成功响应且字段完整时保存。

## 13. 测试策略

### 13.1 注册校验自动化测试

扩展 `tests/register-validation.test.js`，覆盖：

- 空姓名、单字符姓名和超过 100 字符的姓名；
- 错误邮箱格式；
- 少于 8 位和超过 128 位的密码；
- 纯数字密码；
- 后端列出的全部常见弱密码；
- 两次密码不一致；
- 未选择或非法患者类型；
- 空年龄、小数、非数字、0 和超过 120；
- 未勾选知情同意；
- 合法成人和儿童数据。

### 13.2 请求数据自动化测试

新增 `tests/register-payload.test.js`，覆盖：

- 姓名去除首尾空格；
- 邮箱去除首尾空格并转为小写；
- 年龄转换为整数；
- 性别未选择时转换为 `null`；
- 成人和儿童患者类型保持正确；
- 最终对象不包含确认密码及页面状态字段。

### 13.3 微信开发者工具验证

- 问题面板为 0；
- 表单可以完整滚动；
- 输入键盘类型正确；
- 患者类型选中状态明确；
- 性别选择正常；
- 密码显示与隐藏正常；
- 知情同意弹窗和勾选正常；
- 校验失败不发送请求；
- 后端离线时提示清楚且不清空表单；
- 提交过程中不能重复点击；
- 返回登录入口正常。

### 13.4 后端联调验证

后端可用后分别注册一名成人和一名儿童，确认：

- HTTP 201；
- 返回 token 和用户资料；
- 本地存储写入正确；
- 注册后自动进入患者首页；
- 重复邮箱得到友好提示；
- 错误密码策略得到正确提示；
- 后端数据库中的患者资料与提交内容一致。

## 14. 完成标准

只有同时满足以下条件，患者注册功能才算完成：

- 自动化校验测试和请求数据测试全部通过；
- 微信开发者工具问题面板没有新增错误；
- 页面视觉与登录页一致且可以正常滚动；
- 本地校验、错误处理和重复提交保护有效；
- 成人与儿童请求数据都符合后端模型；
- 后端可用时完成真实注册、token 保存和首页跳转闭环；
- 未实现功能没有虚假入口或误导性说明。
