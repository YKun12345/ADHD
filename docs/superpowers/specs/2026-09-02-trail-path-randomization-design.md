# 连线轨迹与认知任务随机化设计

## 目标

让连线任务在正确点击后显示真实连接轨迹，并让每次开始时的节点位置重新排列；同时保证其他认知任务继续使用受约束随机化，降低用户死记答案的可能。

## 方案选择

采用“评分顺序固定、呈现顺序随机”的测量安全方案。连线 A 仍按数字递增，连线 B 仍按数字与字母交替，只有节点空间位置随机；页面使用原生小程序 Canvas 覆盖层连接已正确完成的相邻节点。相比自由拖线，这一方案不会引入触控轨迹误差，也不会改变现有点击评分和错误纠正规则。

其他任务不做无约束洗牌：反应抑制保持 Go/停止目标比例，颜色干扰保持相容/冲突比例，箭头抗干扰保持条件与方向平衡，两步位置记忆保持目标比例，简单反应时随机等待时长，数字广度随机数字内容。协议 ID、题量和报告结构不变。

## 数据与渲染

- `createRandomTrailLayout` 每次从随机源生成新种子，再调用已有无重叠网格布局。
- `buildTrailPath` 根据已完成节点数生成相邻节点线段，错误点击不增加线段。
- 页面每次开始阶段时清空 Canvas；每次正确点击后重新绘制完整已完成路径。
- Canvas 只负责视觉反馈，节点仍是可访问的点击元素；Canvas 不接收触摸，不遮挡作答。
- 页面隐藏、重开阶段或重新测试时不会沿用上一轮路径。

## 测试

- 相同显式种子仍可复现布局，不同随机样本生成不同布局。
- 0/1 个已完成节点不生成线段，后续每完成一个节点增加一段连接。
- WXML 必须包含 Canvas 覆盖层，WXSS 必须保证 Canvas 不拦截点击。
- 七类任务的随机生成测试同时验证题型比例和随机变化。

## 边界

这是辅助筛查交互优化，不宣称与标准临床连线工具等同。正式题量、协议版本、休息规则和结果免责声明保持不变。
