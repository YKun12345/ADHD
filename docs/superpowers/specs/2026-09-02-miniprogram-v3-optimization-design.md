# 小程序整体优化 V3 设计规格

## 决策摘要

采用“共享体验内核 + 既有业务 API 增量增强”的方案。保留当前原生微信小程序、FastAPI、SQLAlchemy 和本地优先缓存架构，不引入新的状态管理框架，也不在移动端加入影像上传或模型推理。所有医疗结果统一使用“辅助筛查/辅助分析，不替代正式诊断”的表述。

## 方案比较与选择

1. **渐进增强（采用）**：复用现有 `ai-copilot`、care API、患者报告 API 和医生工作台，只补共享引导状态、患者页面、协议字段与闭环操作。风险最低，能保护当前未提交成果。
2. 前端演示优先：只做页面和本地 Mock。速度快，但消息、任务和权限无法形成真实闭环，不采用。
3. 全量重构：重写导航、组件和 care 领域。长期边界清晰，但会扩大回归面并覆盖当前分支工作，不采用。

## 架构

### 引导体验

- `guide-state` 以 `user.id + role + guide version` 为命名空间，分别记录登录总引导和页面引导。
- `page-guide-content` 保存经过审核的一句话、帮助提示和页面版本，禁止运行时 AI 生成。
- `onboarding-guide` 是全屏阻断式单屏弹层；遮罩拦截触摸，背景不触发页面操作。
- `ai-copilot` 在页面稳定 300ms 后决定是否显示 6 秒气泡；手动打开始终可用。认知任务仅在 `intro/break/result` 阶段渲染组件。
- 设置页可关闭全部自动介绍、恢复页面介绍、重新查看角色总引导。

### 星仔视觉

- 继续使用代码原生 WXML/WXSS 角色，升级成无圆形外框的小狐狸医生，避免引入位图资源和额外下载。
- 统一名称“星仔 · AI健康小助手”，支持 `idle/wave/happy/thinking/listening/guide/care`。
- 动画仅呼吸、眨眼和挥手；系统减少动态效果时禁用。正式测试阶段组件不渲染。

### 医患闭环

- `care` 领域补齐任务截止时间、派发者显示、过期派生状态、已读时间和未读计数。
- 患者新增“医患消息”和“我的任务”；发送失败的消息保留本地失败态并允许原内容重试。
- 医生患者详情新增任务创建与任务状态列表；任务类型映射到经过白名单校验的患者页面。
- 关怀路径仍是系统建议，不写入 `patient_tasks`，视觉标签明确为“系统建议”；我的任务标记为“医生安排”。

### 专业报告

- 患者报告直接消费已有 `latest_imaging_visualization` 和 `latest_model_prediction`，映射截图、解释、标签、双类概率、置信度、模型版本、生成时间、数据来源和医生说明。
- 区域默认折叠；无数据时只显示“暂无专业评估记录”。医生端只显示相同摘要，不提供上传或推理入口。

### 认知减负

- 正式试次统一为 Go/No-Go 25、简单反应时 20、Stroop/Flanker/2-back 各 24；连线目标约 24 个；数字广度连续两轮失败后自适应结束。
- 协议升级并记录 `protocol_id/schema_version/actual_trials`。报告明确“轻量移动筛查版不可与完整临床工具直接等同”。
- 认知中心默认展示三个短组合，可分天完成；每项显示预计时间，分节休息不计时。

### 每日追踪

- 默认快速记录保持现有必填字段；详细记录按需展开。
- 详细字段进入 FastAPI 请求与数据库模型，不拼接到备注中；活动标签使用字符串数组。
- 弱网仍先本地保存完整 payload，恢复后可沿用现有待同步结构。

### 医生移动工作台

- 首页加入患者姓名搜索、风险筛选、完成状态筛选、待办任务和未读消息摘要。
- 患者详情展示量表、七项认知、趋势、任务、消息、AI 摘要、影像/模型只读摘要。
- NIfTI/GIFTI、3D、截图编辑、模型推理、DAC、安全审计、密钥和批量研究操作不进入小程序。

## 错误与安全

- 所有患者和医生 API 继续使用现有角色守卫；医生只能访问 `assigned_researcher_id` 属于自己的患者。
- 任务跳转只接受内置类型到页面的映射，不执行服务端返回的任意路径。
- 首页和系统通知只显示未读数量，不显示消息正文。
- 空白消息、空白任务说明、非法截止时间、越权患者、重复提交和过期会话均返回明确错误。

## 验收

- Node 测试覆盖共享状态、组件、页面控制器、文案、认知协议、按钮居中和页面主题。
- Pytest 覆盖消息已读、未读数、任务创建/完成/过期、角色和患者归属、扩展追踪字段及报告数据。
- 最终执行全部小程序测试、后端测试、Python 编译、静态检查和仓库测试。
- 微信开发者工具、Android、iPhone、大字体和弱网属于必须人工验收项；当前命令行环境只提供清单，不虚构真机结果。

## 约束

- 所有改动保留在当前 `feature/a-cognitive-experience` 本地工作区。
- 不提交、不合并、不上传，不修改原 A/B 源目录。
- 保留当前工作区已有改动并做增量编辑。
