## 当前技术及四项功能

项目后端为 Python / FastAPI / SQLAlchemy，网页和微信小程序使用 JavaScript；没有 Java / Spring 后端。当前方案采用 Paillier 加法同态加密、AES-256-GCM 认证加密、HMAC-SHA256 完整性校验、JWT HS256 身份认证和 bcrypt 密码哈希，没有引入 SM2、SM3、SM4 等国密算法。

| 功能 | 本轮实现 | 准确的展示表述 |
|---|---|---|
| 隐私保护 | 敏感数据库字段、预测上传文件、影像缓存、私钥和迁移备份采用 AES-GCM；选定量表、认知、追踪数值使用 Paillier 进行密文加法聚合 | 敏感内容加密存储，支持选定数值的同态统计 |
| 身份隔离 | DAC 患者列表、密钥分配和审计结果采用稳定患者代号，姓名和邮箱不向审计身份列表暴露 | 审计视图采用患者代号，身份信息按权限隔离 |
| 权限管控 | 初始化和安全管理限制 DAC；医生按患者绑定、DAC 按有效患者分配控制访问；影像动态入口逐次校验短期会话、绑定与当前患者；关键 API 访问和拒绝记录日志 | 角色与患者范围共同控制访问，关键操作留痕 |
| 可信存证 | 来源内容摘要、密文和元数据绑定校验；授权修改追加版本；启动仅补缺失证据；日志链及受认证头锚检查改动、删除、重排；校验不通过不返回可信统计 | 记录版本和完整性可核验，已覆盖的不一致可追溯 |

授权服务仍能按需解密。登录邮箱、关联编号、任务类型等必要索引元数据保留明文，不能写“所有数据全密文”“彻底匿名”“检测任何篡改”“杜绝数据造假”或“通过 HIPAA 认证”。同态统计并不等于 HGST 神经网络在密文上推理。

## 影像工作区补充

新增 POST /api/v1/imaging/session，使用短期 HttpOnly、SameSite=Strict 会话 cookie，生产启用 Secure。每次动态请求重新检查账户、患者绑定和请求患者，不能因另一个患者标签页替换 cookie 而串用影像。状态与缓存按用户及患者分区，DAC 身份本身不赋予临床影像权限。移除 URL 中的 JWT 和用户对象，患者入口禁止读取共享平台日志。

FINDVIZ_MAX_UPLOAD_BYTES 默认64 MiB，限制整个 multipart 请求；数值时间序列预测上传仍使用 UPLOAD_MAX_BYTES 默认10 MiB。影像在 ASGI 读取前及读取中限制大小，Flask 再限制并以 BytesIO 解析文件，避免原始影像落入明文临时磁盘。诊断日志在进入文件与控制台输出前统一去除用户文件名、标签、数组和异常临床文本；患者请求保留组件、级别、事件、匿名工作区标识及异常类型，CLI 保留固定诊断语句。
