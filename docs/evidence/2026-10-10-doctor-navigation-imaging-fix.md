# 2026-10-10 研究端账号入口与影像可视化修复

## 原因

右上角账号区域只有展示标记，当前页面没有绑定点击处理。影像页面的新版脚本请求 POST /api/v1/imaging/session，但原来监听8000端口的后端进程没有加载新增路由；运行中的 OpenAPI 没有该路径，请求实测返回404。磁盘代码已包含路由，这属于前后端运行版本未同步，不是模型训练错误。

浏览器连续上传两种影像时还复现了初始化竞态：MainViewer.init 提前返回，页面已提示成功，时间序列及相关性初始化请求仍未结束；下一次上传清空工作区后，旧请求产生404与未处理异常。

## 修复

- 六个研究端页面接入共享账号菜单，支持鼠标、Enter/空格、Escape与点击外部收起。显示当前身份，DAC账号提供审计台入口，提供退出登录/切换账号。
- 退出时调用 DELETE /api/v1/imaging/session，清除 HttpOnly影像cookie，再清除浏览器登录与当前患者选择；过期登录也可清cookie，重复退出可用。网络不可达时仍清除本地登录状态，影像cookie最终受原有短期有效期限制。
- 加载更新后的本地后端。旧接口缺失时使用可操作的中文提示，不再只显示Not Found。影像必须经同源授权访问，保留角色与患者绑定检查。
- 等待图形、时间序列和相关性初始请求完成后才提示上传成功。上传过程中禁止重复提交；相关性下拉项采用文本节点写入，无可选序列时禁用相关性入口。
- 清除研究端三个影像跳转来源遗留的URL令牌/用户信息参数，更新静态资源版本，修正文件协议提示。

## 使用

打开 http://127.0.0.1:8000/doctor-web/doctor_patients.html，按Ctrl+F5刷新。点击右上角账号即可退出或切换；从绑定患者的卡片进入影像可视化，上传NIfTI/GIfTI并保存结果。DAC仍按现有账号登录与首次初始化步骤使用。

未替换或训练HGST权重，没有修改PPT。真实HGST分类仍需要兼容的torch/dhg运行环境；本轮解决影像可视化及账号入口，不将模拟分类标记成真实推理。
