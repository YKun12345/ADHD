# 2026-10-10 独立个人中心与较大影像上传修复

右上角原本需要进入独立个人中心，上一轮修复误将医生入口做成了下拉菜单。本轮恢复独立页面，并保留退出时清除影像会话的安全处理。截图中的上传失败在实际服务日志中对应 POST /findviz/upload 返回 413：原来的 64 MB 请求体限制过小，网页只读取 error 字段而忽略后端 detail，导致原因被隐藏。

## 完成的修改

- 医生、DAC 点击右上角进入 doctor_profile.html；患者保留 patient_profile.html。沿用原来的个人中心卡片布局，显示 /auth/me 返回的当前账号姓名、编号和身份，移除固定虚构编号及开发中占位内容。
- 个人中心提供退出登录及工作入口；DAC 的审计入口只向 DAC 显示。退出先清除 HttpOnly 影像会话，再清理当前浏览器登录与患者选择，通过 replace 返回最初的统一登录页 /patient-web/login.html。
- 删除上一轮下拉菜单脚本与样式，更新六个研究端页面引用和缓存版本。账号入口支持鼠标与键盘操作。
- NIfTI/GIfTI 可视化上传默认请求体上限从 64 MB 调整为 512 MB，仍保留带 Content-Length 和分块请求的容量限制、登录与患者绑定检查、内存解析与加密缓存。
- 新增登录后读取上传容量的接口 /api/v1/imaging/upload_limits。上传前按实际服务器配置检查所选文件总大小；发现超限时不清空已有影像工作区。实际 multipart 请求体超过限制时后端仍返回 413。
- 网页同时读取 detail/error；代理返回 HTML 413 时提供文件过大的中文说明。显示当前上传容量，并提示较大 NIfTI 文件可使用 .nii.gz。
- 影像按钮在网络初始化前注册，避免初始化失败后完全没有点击处理。选文件与选截图按钮采用蓝色描边，区别于禁用状态。
- 同步 .env.example、生产环境示例、部署说明、Compose 默认影像容量和 nginx 的 /findviz/ 上传容量；时间序列模型推理的独立上传限制保持原配置。

## 使用

从原来的入口打开网页并按 Ctrl+F5 强制刷新。点击右上角进入独立个人中心；点击退出登录返回 /patient-web/login.html。医生在该统一登录页选择医生/研究人员身份后登录。

从绑定患者的工作台进入影像可视化，选择 NIfTI/GIfTI 文件后点击进入可视化。当前默认每次请求总量 512 MB，包含所有影像文件与 multipart 封装；超过上限时可将 NIfTI 压缩为 .nii.gz，再次选择上传。本轮验证针对影像可视化，不表示真实 HGST 模型依赖已安装或模型已重新训练。
