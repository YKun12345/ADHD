# 知行合“医”录屏与十张截图操作稿

适用当前8000主系统。建议先拍十张图，再分段录制，最后配音剪辑成约4分30秒的视频。以下时间和导出参数是制作建议，具体格式和时长以所报赛项、报名系统正式要求为准。

官方现区分“作品评审视频”和“作品展示视频”：评审视频需要讲定位、创新、实现与实际成果；展示视频偏重使用效果。最省时间的做法是准备一份兼顾讲解和实际操作的评审视频，不要只放页面切换。官方作品截图栏目为1—10张，评审视频和汇报PPT至少提交一项。

来源：[2026材料规范通知](https://www.cmit.cn/html/tongzhigonggao/show-144-45835-1.html)、[2026电脑版提交流程](https://www.cmit.cn/uploadfile/2026/1018/45689.html)。不要套用旧年份的时长要求。

## 录制前

1. 按Ctrl+Alt+B启动8000。小程序登录页“服务器连接设置”使用 `http://127.0.0.1:8000/api/v1`。录本机素材不用先启动公网穿透。
2. 把微信开发者工具的模拟器放大，只框取手机画面。固定同一机型、同一缩放，关闭调试器和多余浮窗；不录代码、控制台、密码或登录过程。
3. 打开三个账号的本机信息：[登录账号.txt](../.codex-tmp/main-examples/登录账号.txt)。小禾用于现场协作，小安用于完整结果，医生用于审核和影像。
4. 网页影像入口：[医生网页登录](http://127.0.0.1:8000/doctor-web/login.html)。登录医生后进入小安档案13的影像工作区。
5. 先拍下面十图，再录会修改资料的操作。不要重建、清空数据库或为了重拍重置账号。

| 身份 | 登录邮箱 | 用途 |
| --- | --- | --- |
| 小禾（用户） | review@competition.example.com | 档案12、评估1；当前有具体补问待答 |
| 小安（用户） | followup@competition.example.com | 档案13、评估2；已有医生意见、计划、随访与影像报告 |
| 林医生 | doctor@competition.example.com | 查看两位示例用户、原件审核、沟通与影像 |

截至本次核对，小禾有1条尚未答复的具体补问。小安的专业计划日期为2026-10-18至2026-10-31，已有1个日期的记录；另有独立的历史自助记录。录制时读页面实际日期，不再把10月18日说成“今天”，也不说已经完成14天专业计划。

## 怎样录制和截图

Windows 11可按 **Win+Shift+R** 选择区域录屏；也可打开“截图工具→录制→新建”。截图用 **Win+Shift+S** 框取手机显示区域，保存图片。[微软操作说明](https://support.microsoft.com/zh-cn/windows/apps/use-snipping-tool-to-capture-screenshots)

每段开始和结束停2秒，操作时缓慢滚动。录错就重录这一段，账号切换和等待载入在剪辑时剪掉。配音可以后录，避免一边操作一边找词。小程序片段保留竖屏比例，剪辑时居中放在横版画布，两侧可放简短流程说明，不横向拉伸页面。

建议最终导出MP4、1920×1080、30fps，配中文字幕；上传前完整播放一遍，确认页面文字可读。截图保留原始清晰图片，上传格式按系统接受类型选择；不要从压缩后的视频再截取。

## 约4分30秒视频：按这八段录

| 成片时间 | 画面与操作 | 解说重点 |
| --- | --- | --- |
| 00:00—00:20 | 作品名称、用户首页与医生工作台各一个短镜头 | ADHD相关评估、资料核对与持续记录容易分散；产品把用户和医生的主要流程放进同一小程序。片头只写作品名称，不放学校、作者等个人身份信息。 |
| 00:20—00:55 | 小禾：首页→评估→打开已有第1轮，展示项目清单、实际提交和待审核状态 | 用户按轮次完成量表与认知任务，执行、质量、医生验收分别记录。本轮预填材料是合成示例，不说成刚刚现场完成。想演示认知交互可补录短练习片段，并标“练习体验”。 |
| 00:55—01:30 | 小安：点星仔→发送“医生发来的计划在哪里看？”或使用页面快捷问题→等待回答，展示业务入口；再轻触星仔展示动作 | 星仔解释使用方法、提示下一步并协助进入业务。应让评委看到实际问答或跳转，不能只展示宠物动作。当前本机规则帮助不表述为已调用DeepSeek。 |
| 01:30—02:20 | 小禾打开“具体补问与答复”→填写合成答复→核对并提交；切医生→选择小禾→第1轮→刷新补问，展示同一条答复与原始提交 | 用户反馈实际保存，医生能在同一档案、同一评估轮次读取；医生查看原件、质量与上下文，再作决定。账号切换和输入密码剪掉。 |
| 02:20—03:10 | 加“已完成闭环示例：小安”的章节字幕；打开小安已发布意见→医生计划→日期记录/阶段回顾→共享沟通 | 医生意见与计划在用户端可读，收到计划和执行记录分别保存。展示已有日期与缺失情况，不把历史自助记录解释成专业计划疗效。可以补录一条当日合成示例记录，等保存成功后再展示。 |
| 03:10—03:50 | 医生网页登录→小安影像工作区→正常载入两个合成NIfTI→拖动切面；切回小程序查看小安系统版与医生审核版影像报告 | 网页负责原始影像交互，小程序负责查看已生成报告与审核版本。输入是合成资料；实际运行原HGST权重不等于证明临床准确率。 |
| 03:50—04:15 | 用简洁流程文字配实际页面回放：评估→原件核对→意见→计划→记录→沟通；可配一张简单架构图 | 说明团队的需求分析、流程与交互设计、业务实现及联调工作；说明小程序与网页如何分工，服务端如何保存轮次、版本与权限。复用模型、开源组件和AI辅助环节如实表述。 |
| 04:15—04:30 | 用户首页、医生工作台和星仔三个短镜头结束 | 强调主要价值：用户知道下一步、医生有原件可核对、计划与随访能持续接上。片尾保留“演示使用合成资料，平台用于辅助筛查与随访”的简短说明。 |

小禾答复可用下面这段合成演示文字，提交前确认当前确是小禾档案：

“【合成演示】本轮主要以学习和阅读情境作答。连续阅读时容易分心，中途休息后可以继续；这里仅展示补充情境的沟通流程。”

本视频允许分段剪辑，但**小禾和小安必须用章节字幕明确区分**，不能把不同账号剪成同一用户刚完成的前后变化。小安已有计划收悉回执，不再假演首次点击收到计划。小禾如要演示首次发布/收悉，应由医生实际完成审核、发布和计划流程后再拍，不能用小安既有结果代替。

## 影像录屏所需文件

这些文件已实际生成，位于项目 `.codex-tmp/main-examples/synthetic-imaging/`：

- `synthetic-competition-functional.nii.gz`：合成功能像，网页选择“功能像”。
- `synthetic-competition-anatomical.nii.gz`：合成结构像，网页选择“结构像”。
- `synthetic-competition-roi90.csv`：合成ROI时间序列；仅用于模型分析入口，不当作NIfTI上传。

医生网页直接入口：http://127.0.0.1:8000/doctor-web/doctor_visualization.html?patient_id=13 。先正常登录医生，再打开此页，选择上述两个NIfTI并载入，等待切片出现后拍摄。CSV与NIfTI独立生成，不宣称两者已证明真实脑区对应。

## 最后导出

建议保存“原始录屏”“配音”“十张截图”“最终视频”四个目录；图片按01—10编号，视频取完整作品名称。片头、片尾和文件名都避免加入学校和参赛人姓名等身份信息；报名承诺书等材料按其各自要求单独提供。

上传前确认：视频既讲产品定位/实现，也展示真实操作；10张图是新版页面；没有密码或真实资料；角色与示例身份不串用。截图和录屏不能代替可运行作品文件。
